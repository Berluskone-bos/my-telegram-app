## Найденные и исправленные баги (проект владельца)
- 401 на заказах: подпись `initData` проверялась неверно (удаляли `signature`, ключ и данные HMAC были переставлены). Теперь из строки проверки убирается только `hash`; секрет = HMAC_SHA256(ключ «WebAppData», токен бота).
- «Заказ оформлен локально»: файлы обновления 4 при загрузке перезаписали более новые. Сайт при ошибке сервера теперь честно показывает ошибку и **не очищает корзину**. Перед сборкой каждого обновления брать свежую `main`.
- Повторное нажатие «Оформить» создавало дубль: добавлен заголовок `Idempotency-Key` (уникальный индекс `orders(user_id, idempotency_key)`), промокод считается атомарно, при нехватке товара — ответ 409.
- Подбор по марке/модели падал на `NOT NULL`: `getCars` не возвращает название модели — берём из запроса (`make_name`, `model_name`).
- В заголовке подбора было «HYUNDAI HYUNDAI CRETA» (марка дважды) — исправлено в обновлении 10.
- PartsAPI иногда обрывает соединение (`SSL: UNEXPECTED_EOF`) на getModels/GetFillVolumes/toDopusk (владелец увидел это в проверочной программе 10.11.2026). Добавлены 3 попытки с паузой и в сервер (`partsapi-cache.js`), и в программу проверки (плюс запасной путь через curl). Данные по Creta (машина № 145603) PartsAPI вернул пустыми — с Railway, не из-за сбоя сети.
- **Подтверждено 11.11.2026:** `toDopusk` принимает `typeId` из каталога ТО (цепочка `toMakes` → `toModels(brandId)` → `toTypes(modelId)` → `typeId`), а не `CAR_ID` из TecDoc. Для Creta II 1.6 4WD 121 л.с. (`typeId=1021020`) `toDopusk` дал всё сразу: объёмы (`specifications[].volume`, л), вязкость и допуски (`properties`), рекомендованные масла (`oils`) по двигателю, АКПП, МКПП, заднему мосту, раздатке, антифризу, тормозной. Поэтому `GetFillVolumes` и `getMakes/getModels/getCars` для подбора больше не нужны (код остался, но не вызывается). Новые переменные Railway: `PARTSAPI_KEY_TOMAKES`, `PARTSAPI_KEY_TOMODELS`, `PARTSAPI_KEY_TOTYPES` (+ уже существующий `PARTSAPI_KEY_TODOPUSK`). VIN: `VINdecode` даёт марку/модель (TecDoc) — используется только как подсказка для выбора. Образцы ответов: `project-files/tools-partsapi/sample-to-*.json`. Дополнительно есть `toParts` (запчасти для ТО по `typeId`: фильтры, колодки) и `toOils` (только рекомендованные масла) — пока не используются.
- Метод `toOils` (пример с сайта PartsAPI, `typeId=9318`, марка VAG) вернул `{items:[{artNumber, commentName, manufactureName, originalName, volume, orderPosition, catalogItemId}]}` — готовые рекомендованные масла (артикулы бренда) по типу машины, `volume` — размер упаковки в литрах, не объём заправки. Это подтверждает, что в каталоге ТО свои `typeId`. Остаётся выяснить цепочку получения `typeId` для нужной машины (`toMakes` → …).
- VIN `Z94…` (Hyundai российской сборки) PartsAPI не знает — это ограничение его базы (VINdecode на TecDoc), не ошибка кода. Приложение предлагает выбор по марке и модели с уже выбранной маркой (по коду производителя WMI).
- `esc` была объявлена в четырёх JS-файлах → `Identifier already declared`, сайт не работал в браузере. Оставлена одна в `products.js`.
- Сайт не отправлял `X-Telegram-Init-Data`, сервер отвечал 401 → заказы не сохранялись (`tg.sendData` не работает при запуске из меню). Исправлено, `sendData` убран.
- Пароль админки был вписан в `admin.html` (публичный репозиторий) → вход по `ADMIN_API_KEY`, проверка на сервере; админка не отправляла ключ и не работала с защищённым API.
- CORS не разрешал `PUT`/`DELETE` → админка не меняла статусы. Исправлено.
- Токены ботов были в истории Git, токен курьерского бота — в `setup-courier-bot.js`. Токены отозваны (02.11.2026), из кода убрано.
- XSS в админке (имена, адреса, комментарии) и в характеристиках товара. Закрыт через `esc()`; проверено тестом (7 срабатываний до, 0 после).
- Курьерские кнопки не проверяли владельца маршрута; webhook курьера принимал не тот заголовок и регистрировался без пути `/webhook/courier`; самостоятельно зарегистрированный курьер сразу активен; TLS к Neon без проверки. Исправлено.
